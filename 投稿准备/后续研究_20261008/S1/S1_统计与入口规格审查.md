## 必须修复项

### MF1 / Important：生产选择资产可以接受工程 fixture 和错误选值

锚点：`tools/entry_gate.py:316–319`，外层调用为 L374–386。`_inventory_identity('dev_selection', receipt)` 只检查阈值属于候选集、inputs=30、children=960、pair_manifest_sha 有240项，并对这些路径重新哈希。它没有调用生产 `validate_pair`，没有验证全30×8矩阵，也没有重新计算八个 total 分数及选值。

只读最小复现（`S1` 表示本目录绝对 Path）：

```python
fixture = load(S1 / 'artifacts/analysis/green_complete_03/dev_fixture/selection_fixture.json')
_inventory_identity('dev_selection', {
    'schema': 'S1.entry.asset.v1', 'asset': 'dev_selection',
    'selected_theta': 8, 'selected_h': 8192,
    'inputs': 30, 'children': 960,
    'pair_manifest_sha': fixture['pair_manifest_sha'],
})
```

实际返回成功。这里 240 个 pair 全部是工程 fixture，真实 fixture 选择为 θ16/h128，复现中的 θ8/h8192 刻意不符。外层的 `test_fixture=false`、`validated=true`、协议值、文件 SHA 和外部冻结 SHA 只约束外层声明及字节，不能补上子 pair 的生产语义和评分验证。此复现调用的是外层在字节门通过后实际使用的语义核验函数，没有修改或替换实现。

修复要求：生产入口对选择记录的每个 pair 使用外部冻结凭据做完整生产核验，拒绝 fixture、缺格、重复及输入不共享；由合格30×8证据重算八分数与 exact-float tie 选择，核对保存结果和完整绑定。选定 P06/P07 的统计入口也应使用经验证的同一选择身份，不能仅凭传入 dict 的候选范围承认“frozen selection”。添加“fixture伪装生产”和“合法候选但错误选值/分数”的真实 RED，再保存新 GREEN。

### MF2 / Important：开始清单及 selected 配置只有非空检查

锚点：`tools/entry_gate.py:320–321`。`start_manifest`、`final_start_manifest`、`selected_configs` 的内容校验只有 `require(entries)`；完全不读取 entry 的身份或配置字段。以下三次只读调用均实际返回成功：

```python
for name in ('start_manifest', 'final_start_manifest', 'selected_configs'):
    _inventory_identity(name, {
        'schema': 'S1.entry.asset.v1', 'asset': name, 'entries': [{}],
    })
```

因此合法冻结一个这种收据后，字节正确也不代表开始清单已经绑定对应 batch、协议、输入全集、binary、配置及真实选择。尤其 `selected_configs` 没有把候选门槛与 MF1 的选择结果作跨资产核对；这正是 SX23“来源参数输入binary一致”的内容要求，而不是额外的源码版本冻结要求。

修复要求：定义所需 entry schema/唯一身份/完整集合，并核验清单中绑定的实际文件和对应资产；正式 selected 配置必须与同一已验证选择的 θ/h、方法及 binary/config 身份一致。缺字段、错误 batch、错误输入集合、selected 值不符必须拒绝，即使外层文件 SHA 正确。添加对应损坏但重新哈希的预制资产测试。

### MF3 / Important：开始入口要求尚未发生的 after A/A

锚点：`tools/entry_gate.py:360–361` 将 `dev_aa_inventory` 放入 DEV_READY 的开始必需项、`formal_aa_inventory` 放入 FINAL_READY 的开始必需项；L294–308 又要求这些库存同时包含 before 和 after 的全部五块。

冻结预注册 §5/L84–88 定义开发/正式矩阵前后分别执行 A/A，after 是该矩阵完成后的观测，不能用提前运行的 A/A 冒充。现有开始门因此产生时序循环：正常开始前缺 after 必然被拒绝；只有绕过入口先执行矩阵，或提前把 after 执行在开始前，才能满足它。

只读复现使用完整的 before dev A/A 身份集合，2方法×2场景×5block=20 entries，调用库存核验后得到 `ValueError: AA inventory missing/duplicate/identity`；代码要求40 entries，包含全部 after。它在读取 pair 前就拒绝，因此不需要运行 A/A 来证明这一时序缺口。正式入口同样要求 before+after 共90块。

修复要求：开始 gate 校验完整 before A/A；矩阵完成/分析 gate 再要求同批完整 before+after，并继续用原 `aa_floor` 计算全 profile 最大绝对 log 包络。保留注册的总数量、五块、seed92001和原统计判据，不改参数或负载。补测试证明“合法 before 可进入开始门，缺 after 仍不能产出完成后的最终判读”。
