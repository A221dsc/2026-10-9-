# S2 独立来源与长期窗口实验报告

日期：2026-10-14。状态：正式运行与独立验收完成；本报告为冻结实验的结果分析。源代码与二进制版本为 **s2-engineering-v1**；结果发布使用独立 Git 标签 **s2-results-v1**，以实际发布记录为准。没有修改 R6、S0/S1、成本表、事件门槛或正式输入，也没有重新筛选或重跑原生计时。

## 1. 研究裁决

**S2 支持“顺序稀疏窗口索引有特定适用区域”，但没有证明 Adaptive R6 比简单门控具有可靠的增量时间优势。**

在独立于 NYC Taxi 的 NASA HTTP 时间分布上，R6 相对 TLX 的优势出现在顺序、稀疏查询场景：计入构建后，在已测的一个窗口周转终点就更快，四个周转时 L01/L02 总时间配对比值中位数分别为 0.5398/0.5309。完整漂移负载 L03 则相反，总时间约为 TLX 的 3.8006 倍。上述方向均通过预注册的严格判据。

真正与自适应控制器相关的比较需要看同布局对照。相对 Event16，9 个 online 和 9 个 total 组均无法可靠区分；相对 Matched LIST，没有组达到可靠更快。完整漂移中，R6 相对 Event16 的逐种子升级次数比值中位数为 0.3951，即减少约 60.49%，但这未转化为可靠的时间优势或最终内存优势。峰值请求字节仅约低 0.52%，也不能包装成显著的空间收益。

因此可以进入**基于现有证据的论文重写与整合**，主线应是适用条件、表示迁移控制和成本边界。若题目和摘要仍以“成本感知控制器显著提高吞吐量”为中心，目前证据不足。本轮不自动启动 S3，也不根据负结果修改算法。

## 2. 问题、输入与公平性

S2 回答三个问题：另一真实时间分布是否支持已有结果；长期运行能否摊销构建成本；成本门控相对简单门控能否减少转换并形成实际收益。

数据来自已归档的 [NASA HTTP July 1995 来源说明](https://ita.ee.lbl.gov/html/contrib/NASA-HTTP.html)。有效记录 1,891,714 条，保留秒级时间和原始行号身份；物理末行 1,891,715 是 8 字节、无时间戳残片，按正式计时前登记的规则排除。严格解析首次失败记录保留。相同秒记录不去重、不添加时间抖动。实际数据只到 7 月 28 日，不声称覆盖完整 31 天。固定时间域仍为 7 月的 2,678,400 秒，不随终点重缩放。

完整键为时间偏移乘以 stride=1,891,716 再加原始行号；半开查询、完整有序输出和记录身份在各方法间一致。窗口是 **N=262,144 条固定记录数量窗口**，每个更新单元先删除当前存活记录，再插入新记录；不是秒数 TTL 窗口。真实时间键上生成的撤销和范围查询仍是合成操作，不能称真实生产索引查询日志。

| 负载 | 插入/删除 | 查询周期 | 运行终点 |
| --- | --- | --- | --- |
| L01 ordered_sparse | 顺序插入、删除最小完整键 | 每 256 更新单元一次 | N、2N、4N |
| L02 ordered_sparse_cancel | 顺序插入；每 256 单元均匀撤销当前存活记录，其余删除最小键 | 每 256 单元一次 | N、2N、4N |
| L03 sparse_shuffle_sparse | 稀疏→乱序且每次随机删除→稀疏 | 三阶段分别 256/8/256 | 同一最长轨迹的 N、2N、4N 前缀 |

L03 三阶段固定为 349,525 / 349,525 / 349,526 个更新单元。**N 终点只有首段稀疏，2N 终点包含部分乱序阶段，4N 才包含完整漂移。** 短实验是真实共同前缀，不重新生成输入或重新定义阶段。查询最近 60 秒，water 是已见最大时间，乱序时不倒退。

| --- | --- |
| M_LIST（Matched LIST） | 同布局常驻 LIST，用于归因；不是原始 PoolHBI 的部署性能复测 |
| M_EVENT_16（Event16） | 同表示与管理约束，采用冻结 DEV 门槛 16 |
| R6 | 原生产 Adaptive PoolHBI 内核；不是 matched Cost 的替代实现 |
| TLX | 历史 TLX B+tree 部署基线，正常 bulk_load；不是同布局消融 |

冻结参数为 epoch=512、min_tree_size=128、PAYBACK=2、K=32、d=4、C=8、max_convert_records=0。成本系数 scan_ns_per_work=1.1427456845204484、conversion_ns_per_record=31.412726323575615；树成本公式与 class 公式见协议，保持原值，未再校准。

## 4. 统计口径与墙钟分辨能力

每个负载/终点/参考方法有 10 个正式输入种子（100001–100010）。对同输入进行 AB/BA 两轮：AB 先参考后 R6，BA 先 R6 后参考，不复用另一个参考组中的 R6 运行。

记 d_i=[log(t_R6,AB/t_ref,AB)+log(t_R6,BA/t_ref,BA)]/2，每个输入的配对比值为 exp(d_i)。比值小于 1 表示 R6 用时更少。报告比值中位数、Q25、Q75、IQR=Q75−Q25 和 wins/10；wins 仅表示比值小于 1 的次数，不等于通过强方向判据。

online 与 total 共 54 项主要比较，采用总体 alpha=0.05 的双侧 Bonferroni Student-t 区间：df=9，临界值 4.836176438767419；log 均值±临界值×样本标准差/√10，再指数化。**这个置信区间估计配对比值的几何均值，不是中位数；IQR 不是置信区间。** build、phase、resource 为探索性描述。

正式前后全部 90 个 A/A 块取 max(abs(log 块比值))，online E=0.1788248941，total E=0.1802116178。分别与 log(1.05) 取较大值得到 D。该 A/A 是本批有限观测包络，不是总体噪声置信上界；不能删除较差块缩小门槛。

可靠更快要求全部 10 个 d_i 以及 log 区间上界严格小于 −D；可靠更慢要求全部 10 个 d_i 以及 log 区间下界严格大于 D；其余“无法可靠区分”。无法区分不表示等效，也不否认可能存在更小效应。


- online：比值门槛约为 0.8363 / 1.1958，需结合全部种子和区间，不只看中位数。


- total：比值门槛约为 0.8351 / 1.1975，需结合全部种子和区间，不只看中位数。

### 6.2 转换数量减少，但收益不能越级推断

L03 的 Event16 升级次数中位数为 320.5，R6 为 134.5。直接用这两个中位数相除并不是配对效应；正确的逐种子 R6/Event16 升级比值中位数为 **0.3951**，Q25–Q75 为 **0.2258–0.4486**，全部 10 个输入都更少。对应的减少比例中位数为 **60.49%**，四分位范围为 **55.14%–77.42%**。

每个 L03 的 R6/Event16 resource 运行中 scheduled_demotions 等于 promotions，cleanup_demotions=0，total_demotions=scheduled_demotions+cleanup_demotions。因此升级加降级的转换事件总数也具有相同配对减少比例；不能把“次数减少 60.49%”改写成“转换时间或 CPU 成本减少 60.49%”。桶大小与单次转换代价不同，S2 没有单独记录转换事件延迟。


![S2_转换与峰值空间](C:/Users/zhangjiacheng/.codex/worktrees/adaptive-poolhbi-s2/小论文/投稿准备/后续研究_20261008/S2/S2_转换与峰值空间.png)


图 3：全部 10 个种子的 L03 R6/Event16 配对资源效应，两面板使用相同纵轴范围。转换次数下降明显，但 whole peak 比值中位数 0.9948，只有约 0.52% 差异；最终占用相同。更多迁移不必然同时存活更多树，因此这两个结果并不矛盾。

## 7. 论文能主张什么，仍不能主张什么

| 论点 | S2 裁决 | 证据与边界 |
| --- | --- | --- |
| 顺序、端点有利且查询稀疏的窗口索引可以比通用 TLX 更省在线时间 | 支持 | L01/L02 及 L03 稀疏前缀；不是任意负载 |
| 计入构建后仍可能形成长期总成本优势 | 支持 | 已测 N、2N、4N 终点；不确定精确回本时刻 |
| R6 比同布局 LIST 稳定提高吞吐 | 不支持 | 无可靠更快组，若干稀疏组可靠更慢 |
| 成本工作量门控比 Event16 稳定提速 | 本批未证明 | 18 项主要时间比较均未可靠分辨 |
| 成本门控可以减少漂移中的表示转换次数 | 支持本输入上的描述性结论 | L03 逐种子转换数比值中位数 0.3951，10/10 更少 |
| 减少转换必然大幅降低峰值或最终空间 | 不支持 | 相对 Event16 峰值仅约低 0.52%，最终相同 |
| 预算和普通降级在这些输入中维持限制并回收树表示 | 支持执行事实 | 峰值≤32、最终0、普通降级有记录 |
| 已证明空树 cleanup、尾延迟改善或 CPU 优化 | S2 无法回答 | cleanup 未触发；未测逐 API/转换延迟或 CPU 采样 |
| 对全部真实系统或多硬件具有普遍优势 | 不支持 | 一个新增领域、单机器、单线程、合成操作 |

对“为什么性能仍不够好”的解释应区分观察和假说。观察到：无转换的顺序稀疏组仍有 R6 相对 Matched LIST 的额外在线时间；复杂漂移时 R6 又明显慢于 TLX。这说明管理路径总成本和底层表示适用性必须计入评价。但 **S2 无 CPU 采样，不能把差值分配成观察缓冲、候选扫描或转换各占百分之几**。S1 的诊断结论只能按其原输入和原环境另行引用。

可写入论文的核心表述为：

> 在固定配置的 NASA 时间键合成操作中，池化时间分桶结构在顺序稀疏场景相对 TLX 显示了含构建成本的优势；该优势不能归因于自适应控制器。成本门控相对事件门控减少了漂移中的表示迁移次数，但未确立可靠的时间或最终空间增益。完整乱序漂移暴露出对通用有序索引的明显劣势。

S2 补上了“另一真实时间分布”和“多个窗口周转”的外部证据。它没有消除 S1 对成本代理增量价值的保留意见，也不应据此将研究宣传成普遍优于简单方法。建议论文用实证边界和机制权衡组织结果，明确保留负结果；此报告完成后再决定是否需要有限的后续诊断，而非直接扩展新算法。
